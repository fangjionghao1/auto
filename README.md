# auto · 稿件生产流水线

订单 txt 从 GitHub 仓库 `src/` 进入 → 登记台账 `src/goal.md` → 生成写作脚手架 → 写作/仿真 → 收尾打包。

## 前置条件

- Python 3，`pip install python-docx`（仅 finalize 需要）
- GitHub CLI（`gh`）已安装并 `gh auth login`
- **无需安装 git**：所有远端操作走 `gh api`，仓库信息直接解析 `.git/config` 与 `.git/HEAD`

## 使用流程

### 1. 订单入库 —— `python watch_src.py [--once] [--interval 秒]`

- `--once` 执行一次后退出；不加则循环执行，默认每 60 秒拉取一次（`--interval` 可调）
- 拉取 GitHub 仓库 `src/` 下的新 txt，下载到本地 `src/` 并写入 `src/goal.md` 台账
- 校验规则：**必填仅「订单时间」「题目」**；缺项 → 改名 `*.faild.txt`；拉取后与本地 goal 表格做「作者+题目」比对（含基准文件 `1.txt`），已存在 → 改名 `*.duplicate.txt`
- 稿件ID 规则：`文件名-MMDD`，一个文件含多个题目时追加 `-1/-2` 序号
- 已处理文件记录于 `.git/watch-src-state.json`（按 文件名+sha 比对：**同名同内容跳过；同名但内容有更新会重新拉取并重新比对/登记**）
- 追加台账行时会自动把整表按列宽对齐重排、清除表格行之间的空行（空行会打断 Markdown 表格渲染）及全空占位行

订单 txt 格式示例（部门/采编/类别/作者/目标等级/状态/备注均可选）：

```
部门：XX部
采编：张三
订单时间：2026-09-29 10:00
类别：EI会议
作者：李四
题目：基于XXX的YYY研究
```

### 2. 生成写作脚手架 —— `python generate_src.py`

- 为 goal.md 中**进度不是「完成/已完成/进行中」**的每一行生成工作目录：
  `gen/artifacts/{稿件ID}/{状态}/{标题}/`，内含参数化后的 `src.md`（模板来自 `gen-src-repo/src.md`，替换 §0 参数区的文章题目/预投期刊/目标语言）和 `speek.md` 副本
- 语言规则：类别以「EI会议」开头 → 中英双稿，否则 → 中文稿
- 生成后自动把对应行的进度标记为「**进行中**」（只改本地 goal.md，不同步远端）

### 3. 写作与仿真（脚本之外）

在第 2 步生成的目录里产出 `论文.md`、`*.docx`、`仿真/` 目录及仿真文件。

### 4. 收尾打包 —— `python finalize_artifacts.py`

- 遍历 `gen/artifacts/*/*/*` 中**已含 `论文.md`** 的稿件目录：
  - 写 `仿真/env.txt`（MATLAB R2025b、随机种子 42、合成场景）
  - 给每个 docx 加居中页脚「第 X 页」（Word PAGE 域）
  - 把 `仿真/` 打成 `仿真/仿真打包.zip`
  - 打印参考文献前的中文字数与 zip 文件数
- 注意：`仿真/` 目录需事先存在，否则报错

## goal.md 台账列

| 列 | 说明 |
| --- | --- |
| 稿件ID / auth / type / 标题 | 稿件标识、作者、类别、题目 |
| 目标等级 / 状态 / note | 默认 正常 / V1 / 空 |
| 进度 | 驱动 generate：空/待重设计→生成；进行中→跳过；完成/已完成→跳过 |
| src / 产物路径 | 订单 txt 来源、产物目录 |
