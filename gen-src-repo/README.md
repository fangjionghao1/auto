# 论文闭环验证规则 · VERIFICATION SPEC

> **定位**：本项目**交付门禁**的唯一权威说明
> **验证人**：Guard（论文编写项目总负责人 / 守门人）

---

## 一、目的与适用范围

| 项 | 说明 |
| :--- | :--- |
| **目的** | 在交付前把"低级错误、数据失真、跑题、不达发表标准"四类问题拦在门内 |
| **适用范围** | 本项目所有中文/英文稿件：普刊、指定普刊、科技核心、EI 会议、只写不发 |
| **不适用** | 期刊方的排版、查重、伦理审查流程（属外部环节，本项目只保证交付物达标） |

---

## 二、三条核心原则

1. **可复现**：同一稿件、同一版本、同一规则，任何人重跑应得到同一结论。规则写死在本文档，不依赖"当时感觉"。
2. **留痕**：每次验证必须产出报告，记录**稿件版本（文件哈希）+ 验证时间 + 结论 + 证据（页码/行号/原句）**。无证据的结论视为无效。
3. **门禁**：验证不是建议，是闸门。存在 **Blocker** 时**一律不得交付**，无论进度多紧。

---

## 三、闭环流程

```text
  ┌───────────┐
  │ 撰写完成   │
  └─────┬─────┘
        ▼
  ┌───────────────────────────────────────────┐
  │ 第一轮验证：V1 文字术语 → V2 数据图表        │
  │            → V3 主题契合 → V4 审稿人评估    │
  └─────┬─────────────────────────────────────┘
        ▼
  ┌───────────┐   有 Blocker   ┌───────────┐
  │ 出具报告   │ ────────────▶ │ 修订稿件   │──┐
  └─────┬─────┘                └───────────┘  │
        │ 无 Blocker                          │
        │        ▲────────────────────────────┘
        │        │  增量复审（只复验改动点 + 受影响项）
        ▼
  ┌───────────┐
  │ 放行交付   │ → 计入 goal 进度（已交付 1.0）
  └───────────┘
```

**关键约束**

- 修订后**必须复审**，不得"改完直接交付"。
- 复审采用**增量策略**：只复验被修改的段落及其影响面（如改了数据 → V2 全量重跑）。
- 同一稿件最多 **3 轮** 全量返修；第 3 轮仍不通过 → 升级为**挂起**并登记阻塞项。

---

## 四、严重度分级

| 等级 | 标识 | 含义 | 处理 |
| :--- | :--- | :--- | :--- |
| 阻断 | `Blocker` | 直接影响发表资格或造成学术风险 | **必须修复**，否则不得交付 |
| 严重 | `Major` | 影响可读性/严谨性，审稿人大概率指出 | 必须修复 |
| 一般 | `Minor` | 细节瑕疵，不影响理解 | 建议修复，可计入"Issue 清单"批处理 |
| 提示 | `Info` | 主观优化建议（措辞、排版偏好） | 记录，作者决定是否采纳 |

**一票否决（直接判 `Blocker`，不进入打分环节）**

- 抄袭、剽窃、代写等学术不端；
- 数据造假、篡改、选择性剔除不利数据；
- 一稿多投、署名争议、利益冲突未声明；
- 图表/数据无原始来源支撑且无法解释。

## 五、验证项详规

### V1 · 文字与术语

**V1.1 错别字与文字错误**

| 检查点           | 示例 / 判定             | 等级                    |
| :------------ | :------------------ | :-------------------- |
| 形近字、同音字误用     | "实验"↔"试验"、"权利"↔"权力" | Minor（正文语义受影响时 Major） |
| 多字 / 漏字 / 重复字 | "的的"、"进行行"          | Minor                 |
| 词语搭配不当        | "提高效率的速度"           | Major                 |
| 语病            | 成分残缺、句式杂糅、主谓不搭      | Major                 |
| 中英文标点混用       | 中文句中夹半角 `,` `.` `;` | Minor                 |
| 全半角 / 引号括号未配对 | `"` 未闭合、`（）` 缺半边    | Minor                 |
| 数量与单位书写       | 数字与单位间空格、量符号斜体      | Minor                 |
| 千分位、精度书写不一致   | 同一量 3 位/4 位小数混用     | Minor                 |

**V1.2 专业名词合理性**

| 检查点 | 判定标准 | 等级 |
| :--- | :--- | :--- |
| 首次出现给全称 + 缩写 | 格式：`中文全称（English Full Name, ABBR）`，如"卷积神经网络（Convolutional Neural Network, CNN）" | Major |
| 缩写全文统一 | 同一概念不得出现两种缩写 | Major |
| 中英文术语对应准确 | 采用学科惯用译法，不得自造 | Major |
| 术语符合国家/学科规范 | 优先采用 GB/T 术语标准或学科权威译名 | Major |
| 术语一致性 | 全文同一概念用词统一（不得"神经网络"↔"神经网路"） | Minor |
| 避免口语化/自造词 | "超级好用"、"大概差不多" | Major |
| 外文文献人名/机构名规范 | 首次给出中文译名 + 原文 | Minor |
| 专业符号规范 | 变量斜体、单位正体、下标含义明确 | Minor |

**输出要求**：逐条给出 `原文摘录 → 位置（章节/段落/页码）→ 问题类型 → 建议改法 → 等级`。

---

### V2 · 数据图表与论文内容一致性

**V2.1 数值一致性**

| 检查点 | 判定 | 等级 |
| :--- | :--- | :--- |
| 正文引用数字 = 图表内数字 | 精确比对（允许四舍五入一致） | **Blocker** |
| 正文结论方向 = 图表趋势 | 如正文称"显著上升"，图表须上升 | **Blocker** |
| 表格分项合计 = 总计 | 逐行/逐列验算 | **Blocker** |
| 百分比合计 = 100%（或已说明） | 含"其它"项 | Major |
| 同一数据多处出现数值一致 | 摘要 / 正文 / 图表 / 结论 四处交叉 | **Blocker** |
| 单位、量纲、精度一致 | 换算正确（如 mm↔cm） | Major |

**V2.2 编号与引用一致性**

| 检查点 | 判定 | 等级 |
| :--- | :--- | :--- |
| 图表编号连续、无跳号重号 | 图 1、图 2…… 表 1、表 2…… | Major |
| 正文引用编号 = 实际图表编号 | "如图 3 所示"须真对应图 3 | **Blocker** |
| 公式编号连续、引用正确 | 式 (1)(2)…… | Major |
| 图题 / 表题位置与格式统一 | 图题在下、表题在上（或全文统一） | Minor |

**V2.3 图表自洽与可读性**

| 检查点 | 判定 | 等级 |
| :--- | :--- | :--- |
| 坐标轴有物理量与单位 | 缺失即指出 | Major |
| 图例齐全、与图内元素对应 | 线型/颜色/标记可区分 | Major |
| 误差棒 / 置信区间 / 显著性标注 | 有统计结论必须标注 | Major |
| 分辨率、清晰度、字体可读 | 缩放后不失真 | Major |
| 图表数据可回溯 | 能对应到原始数据/附表/出处 | **Blocker**（无法解释来源时） |
| 表格三线表规范、无空单元格歧义 | 空值须标注"—"或"NA" | Minor |

**输出要求**：以"图/表编号 → 问题 → 正文对应位置 → 证据（双方数值）"的对照表列出。**V2 为强制全量项，任何改动后必须重跑。**

---

### V3 · 内容与主题契合度

| 检查点 | 判定标准 | 等级 |
| :--- | :--- | :--- |
| 标题 ↔ 正文 | 正文主体须覆盖标题全部限定词（对象/方法/场景/限定条件） | **Blocker**（核心掉项） |
| 摘要四要素 | 研究对象 · 方法 · 主要结果 · 结论，缺一即 Major | Major |
| 摘要 ↔ 正文 | 摘要中的数据与结论须能在正文找到出处，不得出现正文没有的结论 | **Blocker** |
| 关键词 ↔ 主题 | 关键词须为正文高频核心概念，不得出现正文未涉及的词 | Major |
| 章节服务主题 | 逐节问"这一节删掉，主题是否受损？"无贡献章节 = 冗余 | Major |
| 引言 ↔ 结论 | 引言提出的问题/假设，结论须逐一回应 | **Blocker** |
| 逻辑链完整 | 问题 → 方法 → 证据 → 结论 无断点 | Major |
| 跑题风险扫描 | 出现与主题无关的大段背景、综述、案例 | Major |
| 文献与主题相关 | 引文须支撑主题，无关堆砌 | Minor |

**判定口径**：若"标题承诺的内容"与"正文实际提供的"存在**核心要素缺失或整体偏移**，判 `Blocker`（偏题）；若仅为局部冗余或侧重偏差，判 `Major`。

**输出要求**：给出 **主题—章节覆盖矩阵**（行=主题要素，列=章节，格=覆盖/部分覆盖/未覆盖），并指出未覆盖项。

---

### V4 · 专业审稿人视角：发表资格评估

**V4.0 前置**：先跑完"一票否决"扫描（见第四节），命中即终止 V4 并判 `Blocker`。

**V4.1 评分卡（满分 100）**

| 维度         | 权重  | 评分要点                         |
| :--------- | :-- | :--------------------------- |
| 创新性 / 学术贡献 | 25  | 是否提出新问题、新方法、新证据；与已有工作的差异是否明确 |
| 方法严谨性      | 20  | 实验/研究设计合理、变量控制、样本量、可重复性      |
| 数据与论证充分性   | 20  | 数据量是否支撑结论、统计检验恰当、对照合理        |
| 结论可靠性      | 15  | 结论是否被数据支撑、有无过度外推             |
| 结构与表达      | 10  | 逻辑清晰、语言规范、图表规范               |
| 参考文献       | 10  | 规范性、时效性（近 5 年占比）、覆盖关键文献、格式统一 |

**V4.2 结论阈值**

| 总分 | 结论 | 处理 |
| :--- | :--- | :--- |
| ≥ 85 | **具备发表资格**（Recommend Accept） | 修复 `Major` 及以下问题后放行 |
| 70 ~ 84 | **修改后可发表**（Minor/Major Revision） | 出修订清单，返修后复审 |
| < 70 | **暂不具备资格**（Reject / 大修） | 判 `Blocker`，需大修并说明改进路径 |

**V4.3 审稿意见撰写要求**

以审稿人视角输出：

1. **总体评价**（2~3 句，含亮点与主要短板）；
2. **主要问题**（Major，编号列出，每条给出"问题 + 依据 + 修改建议"）；
3. **次要问题**（Minor，可合并列出）；
4. **是否推荐发表**及理由；
5. **目标期刊匹配度**：对照稿件等级（普刊/科技核心/EI）判断体量与深度是否匹配。

---

## 六、放行门禁规则

稿件可交付（计入目标）当且仅当**同时满足**：
0
- [ ] V1 完成，无 `Blocker`、无未处理 `Major`；
- [ ] V2 完成且**全量重跑**，无 `Blocker`、无未处理 `Major`；
- [ ] V3 完成，主题覆盖矩阵无"未覆盖"核心要素；
- [ ] V4 完成，总分 ≥ 70 且无"一票否决"命中；
- [ ] 报告已归档并记录稿件版本哈希；
- [ ] 修订轮次 ≤ 3。

**任一项不满足 → 不得交付**，状态回退至"自查中"。
